# Issue Structuring Methodology

## What is Issue Structuring?

Issue structuring is the process of breaking down complex business problems into manageable, answerable components using the MECE (Mutually Exclusive, Collectively Exhaustive) principle.

## Core Principles

### MECE Principle

**Mutually Exclusive (ME)**:
- Categories don't overlap
- No double-counting
- Clear boundaries

**Collectively Exhaustive (CE)**:
- All possibilities covered
- No gaps or omissions
- Complete coverage

## Issue Tree Development

### Step 1: Define the Central Issue

Frame as a question:
- "Should we enter market X?"
- "How can we increase profitability?"
- "What is the optimal pricing strategy?"

### Step 2: Break Down into Sub-Issues

Use MECE frameworks:

**Example: Revenue Decline**
```
Why is revenue declining?
├─ Volume decrease
│  ├─ Customer acquisition down
│  └─ Customer retention down
└─ Price decrease
   ├─ Competitive pressure
   └─ Product mix shift
```

### Step 3: Continue Breaking Down

Until issues become:
- Answerable with data
- Actionable
- Specific enough to analyze

## Common MECE Frameworks

### By Formula
```
Profit = Revenue - Cost
├─ Revenue = Price × Volume
└─ Cost = Fixed + Variable
```

### By Process
```
Operations
├─ Input (Procurement)
├─ Process (Manufacturing)
└─ Output (Distribution)
```

### By Segment
```
Market
├─ Product A
├─ Product B
└─ Product C
```

### By Time
```
Analysis Period
├─ Short-term (0-1 year)
├─ Medium-term (1-3 years)
└─ Long-term (3+ years)
```

## Types of Issue Trees

### What Tree
- Identifies problem components
- Diagnostic focus
- "What is happening?"

### Why Tree
- Identifies root causes
- Causal focus
- "Why is it happening?"

### How Tree
- Identifies solutions
- Prescriptive focus
- "How can we fix it?"

## Best Practices

### Do's
✅ Start with clear central issue
✅ Use consistent MECE logic at each level
✅ Keep levels at similar depth
✅ Make issues specific and measurable
✅ Ensure actionability

### Don'ts
❌ Mix different MECE frameworks at same level
❌ Create too many levels (usually 3-4 is sufficient)
❌ Use vague or ambiguous categories
❌ Include overlapping categories
❌ Leave gaps in coverage

## Application Process

1. **Define**: State the core business challenge
2. **Decompose**: Break into MECE components
3. **Prioritize**: Focus on critical issues
4. **Hypothesize**: Form testable hypotheses
5. **Analyze**: Gather data and validate
6. **Synthesize**: Draw conclusions
7. **Recommend**: Propose actions

## Example: Market Entry Decision

```
Should we enter market X?

├─ Is the market attractive?
│  ├─ Market size and growth?
│  ├─ Profitability potential?
│  └─ Competitive intensity?
│
├─ Can we win?
│  ├─ Do we have competitive advantage?
│  ├─ Can we overcome entry barriers?
│  └─ Do we have required capabilities?
│
└─ Is it worth it?
   ├─ Financial returns acceptable?
   ├─ Risks manageable?
   └─ Strategic fit with portfolio?
```

## Common Pitfalls

### Overlapping Categories
❌ Bad:
```
Sales by channel:
- Online
- Retail
- Mobile app (overlaps with online)
```

✅ Good:
```
Sales by channel:
- Online (web only)
- Mobile app
- Physical retail
```

### Incomplete Coverage
❌ Bad:
```
Customer segments:
- Large enterprises
- Small businesses
(Missing: Medium-sized businesses)
```

✅ Good:
```
Customer segments:
- Large enterprises (>1000 employees)
- Medium businesses (100-999 employees)
- Small businesses (<100 employees)
```

## Tools and Techniques

### Pyramid Principle
- Start with answer
- Group supporting arguments
- Arrange logically

### Hypothesis Tree
- State hypothesis at each node
- Test systematically
- Refine based on findings

### Decision Tree
- Map decision points
- Identify criteria
- Evaluate options
