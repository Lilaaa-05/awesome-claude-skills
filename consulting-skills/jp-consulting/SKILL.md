# コンサルティングアウトプット生成スキル(さよならコンサル！)

**設計思想**: 段階的構築(Incremental Build) × スライド指向(Slide-First Approach)
**基本理念**: 戦略・総合・テクノロジーコンサルティングの品質基準を実現
**主要機能**: 
- イシュー駆動型の課題設定
- 仮説検証型フレームワーク分析
- データに基づくスライド構成
- 複数企業フォーマット対応
- 進捗可視化スライド構成
- より豊富な分析コンテンツ

---

# 📌 スキルの基本方針

## 対話の進め方

本スキルでは、ユーザーとの対話を通じて段階的に情報を収集します。

**初回の対応**:
- ユーザーが取り組みたい課題を簡潔に尋ねる
- 企業フォーマットの希望を確認
- 一度に多くの情報を求めない
- 過度に詳細なヒアリングは避ける

**作業開始のタイミング**:
- 課題の概要が把握できた時点
- 企業フォーマットが確定した時点
- または、ユーザーから作業開始の意思表示があった時点

**情報が不足している場合**:
- 最も重要な1-2点のみ追加で確認
- 詳細は作業を進めながら段階的に確認

## 🏗️ 設計思想の背景

**特徴**:
- 全体構成を先に固めてから、各スライドの詳細に入る
- 各スライドは独立して作成可能(モジュール設計)
- 中断・再開が容易な設計
- 進捗状況の可視化

**コンテキスト効率化**:
- 必要な情報のみを順次読み込み
- 作業完了後は不要な情報を保持しない
- スライド単位での区切りにより、長尺資料でも対応可能

**進捗管理**:
- ✅ 作成済みスライドの明示
- 📝 作成中スライドの表示
- ⬜ 未作成スライドの表示
- 進捗率の自動計算

## 📋 作業フローの全体像

本スキルは4つのフェーズで資料を完成させます:

### Phase 0: 企業フォーマット選択 (所要時間: 2-3分)
- 利用可能なフォーマットの提示
- ユーザーの選択確認
- 選択フォーマットの特性理解

### Phase 1: 問題設定 (所要時間: 20-30分)
- イシューの明確化と構造化
- 検証すべき仮説の設定
- フレームワークの選定
- より深い分析視点の追加(EYのNexus思考など参考)

### Phase 2: 資料構成の設計 (所要時間: 15-20分)
- ストーリーラインの構築
- 作成流れファイルの作成(作成流れ.md形式)
- 各スライドのデータ要件定義
- **進捗ステータスの初期化(全て⬜未作成)**

### Phase 3: スライド作成 (所要時間: 40-80分)
- 1枚ずつデータ収集とスライド生成
- **完成したスライドに✅マーク付与**
- 各スライド完成後、品質確認
- **進捗率の更新**
- ユーザー確認を得てから次へ進行

### Phase 4: 品質確認 (所要時間: 10-15分)
- 全体の整合性チェック
- 品質基準との照合
- 最終調整

**標準所要時間**: 約90-120分(スライド枚数とフォーマットによる)

```
「このプロジェクトの第○枚目から再開してください」
```

# 📖 各フェーズの詳細手順

## フェーズ1-A: イシューの特定(強化版)

**作業内容**:
ユーザーの要望から、本質的に答えるべき「問い」を抽出します。

**実施事項**(選択されたフォーマットに応じて調整):
- 課題の背景と制約条件の確認
- 答えを出すべき中心的な問いを定式化
- MECE原則に基づく論点の構造化
- プロジェクトの成功基準を定義
- **【EYスタイルの場合】Nexus視点(人・技術・創新)での分析追加**
- **【BCGスタイルの場合】ストーリーナラティブの構築**
- **【Deloitteスタイルの場合】リスク視点の統合**
- **業界トレンドとマクロ環境の分析追加**
- **ステークホルダー分析の追加**

**成果物の形式**:
```markdown
## 設定した中心的イシュー
[「○○すべきか」形式の問い]

## 論点の構造(MECE分解)
[中心的イシュー]
├─ 第一の検討軸
│  ├─ 具体的論点A
│  └─ 具体的論点B
├─ 第二の検討軸
│  ├─ 具体的論点C
│  └─ 具体的論点D
└─ 第三の検討軸
   ├─ 具体的論点E
   └─ 具体的論点F

## プロジェクトのゴール
- [達成すべき状態]
- [期待される成果]

## 評価指標(KPI)
- [指標1: 具体的な数値目標]
- [指標2: 具体的な数値目標]
- [指標3: 具体的な数値目標]

## ステークホルダー分析
- [主要関係者1]: 期待値と影響力
- [主要関係者2]: 期待値と影響力

## マクロ環境分析(PEST)
- 政治的要因(Political)
- 経済的要因(Economic)
- 社会的要因(Social)
- 技術的要因(Technological)
```

**作業内容**:

- 【⬜ 独立型】他のスライドに依存せず作成可能

- 【⬜ 総括型】後のスライドまたは分析フレームワークが必要(サマリーや目次など)

## フェーズ3: スライド作成の実行(進捗可視化対応)

**基本方針**: 全スライドをまとめて1つのMarkdownファイルに出力し、各ステップで更新

**この方式を採用する理由**:
- 一度に全体構成を把握できる
- 各スライドの更新が容易
- **進捗状況が一目でわかる**
- 企業フォーマット適用が簡単
- 最終的な調整がしやすい

**出力ファイル名**: `[プロジェクト名]_演示稿_[日付].md`

**1枚あたりの作業フロー**(進捗管理統合・ユーザー確認重視):
```
【作業手順】(各スライド共通)

ステップ0: 前提確認と進捗表示
   - 作成流れファイルでスライドの関連性を確認
   - 進捗ステータスを確認(⬜→📝に変更)
   - **進捗表をユーザーに表示**
     * 完成済み: ✅マーク付きスライド一覧
     * 作成中: 📝マーク(現在のスライド)
     * 未作成: ⬜マーク付きスライド一覧
     * 進捗率: 「X/XX枚完成(Y%)」
   - 「独立」の場合: そのまま進行
   - 関連性がある場合: 必要条件を満たしているか確認
     * 参照先スライドの完成状況(✅マークを確認)
     * 必要資料の提供状況
     * 不足があれば、ユーザーに状況説明と対応方針を提示
     * 了承を得てから作業継続

ステップ1: 作成流れファイルから当該スライドの設計仕様を読み取る

ステップ2: 指定された情報源を基にWeb検索実施(3-8回程度、フォーマットにより調整)

ステップ3: 収集データの整理と分析

ステップ4a: **スライドイメージ図の提示**
   - スライドの視覚的構成を図解
   - レイアウト配置(タイトル、本文、図表の位置)
   - 主要な図表の種類(棒グラフ、折れ線グラフ、マトリクス等)
   - 色彩・強調ポイント
   - **ASCII アート形式またはMarkdown図解で表現**
   
   例:
   ```
   ┌─────────────────────────────────┐
   │ タイトル: 市場規模の推移      │
   ├─────────────────────────────────┤
   │ メッセージ: 市場は年10%成長   │
   ├─────────────────────────────────┤
   │        [折れ線グラフ]          │
   │     ↗                          │
   │   ↗    2020-2025実績           │
   │ ↗      2026-2030予測           │
   ├─────────────────────────────────┤
   │ So What: 今が参入好機         │
   │ 出所: ○○調査                  │
   └─────────────────────────────────┘
   ```

ステップ4b: **スライド構成の説明**
   - このスライドの目的と役割
   - 含まれるデータと情報
   - **図表の統合方針**: 複数データは一つの図表にまとめる(複合グラフ、マトリクス、比較表等)
   - フォーマット固有の要素
   - レイアウトの意図

ステップ4c: **ユーザー確認(イメージ図承認)**
   「このイメージ図で作成してよろしいですか?修正が必要な点があれば教えてください」
   - ユーザーからOKが出るまで待機
   - 修正要望があればイメージ図を調整

ステップ5: スライド原稿の作成(設計仕様とイメージ図に忠実に)
   - 選択された企業フォーマットを適用
   - フォーマット固有のデザイン要素を組み込み
   - Markdownファイルの該当スライド部分を更新

ステップ6: 品質確認(8項目に拡張)
   □ レイアウトの整合性(フォーマット基準)
   □ 図表形式の整合性
   □ 実データの使用(推定値の場合は明記)
   □ 示唆の明示(So What明確)
   □ 出所の記録(URL含む)
   □ メッセージの明確性(1スライド1メッセージ)
   □ フォーマット固有要素の確認
   □ アクション指向性の確認

ステップ7: 完成スライドをユーザーに提示

ステップ8: **ユーザー確認(内容承認)**
   「第○枚が完成しました。以下の内容でよろしいですか?」
   [完成したスライド全文を表示]
   
   「修正が必要な箇所があれば具体的にお知らせください。」
   「問題なければ『OK』『次へ』などとお伝えください。」
   ```

## 📞 サポートとトラブルシューティング

### よくある質問

**Q: フォーマットを途中で変更できますか?**
A: 一貫性のため推奨しませんが、新しいフォーマットで全体を再生成することは可能です。

**Q: 複数のフォーマットを混合できますか?**
A: 基本的に1つのフォーマットで統一することを推奨しますが、
   特定のスライドのみ異なるスタイルを適用することも可能です。

**Q: 進捗ステータスが正しく更新されない場合は?**
A: 構成ファイルを手動で確認・修正し、再度アップロードしてください。

**Q: 作業を中断して数日後に再開できますか?**
A: はい。構成ファイル(進捗付き)と演示稿ファイルをアップロードすれば、
   正確な位置から再開できます。

**Q: カスタムフォーマットを作成できますか?**
A: 現時点では8つの標準フォーマットのみですが、
   「標準」フォーマットを選択し、具体的な要件を伝えることで
   カスタマイズが可能です。
