## 1. 仮説思考とは

**仮説思考**: 限られた情報から「仮の答え」を先に立て、それを検証しながら進める思考法

### なぜ仮説思考が重要か

#### 従来型（網羅的分析）の問題点
```
問題発生 → 全データ収集 → 全パターン分析 → 答え
             ↑ 時間がかかりすぎる
             ↑ 本質的でないデータも収集
             ↑ 分析が発散する
```

#### 仮説思考のアプローチ
```
問題発生 → 仮説立案 → 重要データ収集 → 検証 → 答え
             ↑ 方向性が明確
             ↑ 必要なデータだけ収集
             ↑ 効率的に答えにたどり着く
```

### 仮説思考のメリット

1. **スピード向上**
   - 必要なデータだけに絞れる
   - 分析の方向性が明確

2. **深い洞察**
   - 本質的な因果関係を考える
   - 表面的な分析に留まらない

3. **行動指向**
   - 完璧なデータを待たない
   - 不確実性の中でも意思決定できる

## 2. ゼロベース思考

仮説を立てる際の基本姿勢。

### ゼロベース思考とは

既成概念や前例にとらわれず、白紙の状態から考える思考法。

### ゼロベース思考の実践

#### NG: 過去の延長線
```
❌ 「去年もこうだったから、今年も同じ」
❌ 「業界の常識では〇〇だから」
❌ 「うちの会社では無理」
```

#### OK: ゼロから問う
```
✅ 「もし今日から始めるとしたら、どうするか？」
✅ 「この前提は本当に正しいのか？」
✅ 「なぜそれが当たり前なのか？」
```

### 質問のテンプレート

1. **前提を疑う**
   - 「この前提は本当に正しいか？」
   - 「なぜそうなっているのか？」
   
2. **制約を外す**
   - 「もし制約がなかったら？」
   - 「もし予算が10倍あったら？」
   
3. **逆から考える**
   - 「反対のことをしたらどうなるか？」
   - 「最悪のシナリオは何か？」

## 3. 仮説の立て方

### 良い仮説の3条件

1. **検証可能（Testable）**
   - データで確認できる
   - 明確な判断基準がある

2. **具体的（Specific）**
   - 曖昧でない
   - 数値化されている（可能な場合）

3. **アクショナブル（Actionable）**
   - 検証結果が意思決定につながる
   - 実行に移せる

### 仮説の形式

#### パターン1: 因果関係仮説
```
【仮説】Xが原因で、Yが起きている
【例】価格が高いため、若年層の購入が減少している

検証方法: 価格と若年層購入量の相関分析、競合価格比較
```

#### パターン2: 比較仮説
```
【仮説】AよりBの方が優れている
【例】新規市場参入は、既存市場深耕より収益性が高い

検証方法: 両市場の収益性試算、リスク評価
```

#### パターン3: 予測仮説
```
【仮説】Xを実行すれば、Yの結果が得られる
【例】価格を10%下げれば、販売量が20%増加する

検証方法: 過去の価格弾力性分析、テスト販売
```

### 仮説立案のステップ

#### Step 1: 観察・情報収集
```
- ユーザーの発言
- 既知の事実
- 業界の状況
- 過去のデータ
```

#### Step 2: パターン認識
```
- 共通点は何か？
- 異なる点は何か？
- 因果関係はありそうか？
```

#### Step 3: 仮説の言語化
```
「〇〇が原因で、〇〇になっているのではないか」
「〇〇すれば、〇〇が改善するのではないか」
```

#### Step 4: 検証方法の設計
```
- どのデータが必要か
- どう分析するか
- 判断基準は何か
```

### 仮説立案のテクニック

#### テクニック1: 類推（アナロジー）
```
類似の事例から学ぶ

例: 「A業界で成功した戦略は、B業界でも通用するか？」
   「スマホ市場の成長パターンは、IoT市場にも当てはまるか？」
```

#### テクニック2: 逆説的発想
```
常識の逆を考える

例: 「価格を下げる代わりに、上げたらどうなるか？」
   「顧客を増やす代わりに、減らしたらどうなるか？（絞り込み）」
```

#### テクニック3: 分解と組み合わせ
```
要素に分けて、新しい組み合わせを考える

例: 「製品Aの技術」×「製品Bのデザイン」×「製品Cの価格」
   = 新製品コンセプト
```

#### テクニック4: Why を5回繰り返す
```
表面的な理由から、本質的な原因を見つける

例:
Q1: なぜ売上が減ったのか？
A1: 顧客数が減ったから

Q2: なぜ顧客数が減ったのか？
A2: リピート率が下がったから

Q3: なぜリピート率が下がったのか？
A3: 商品の品質問題があったから

Q4: なぜ品質問題が起きたのか？
A4: 生産プロセスの変更があったから

Q5: なぜプロセスを変更したのか？
A5: コスト削減のため

→ 【仮説】コスト削減が品質低下を招き、顧客離れにつながった
```

## 4. 仮説の検証

### 検証の基本ステップ

#### Step 1: 検証計画の策定
```
1. 必要なデータの特定
2. データ収集方法の決定
3. 分析手法の選択
4. 判断基準の設定
```

#### Step 2: データ収集
```
優先順位:
1. 既存データ（社内、公開情報）
2. 簡易調査（Web検索、フェルミ推定）
3. 詳細調査（ユーザー提供、専門調査）
```

#### Step 3: 分析と評価
```
- データは仮説を支持するか？
- 反証はないか？
- 代替仮説は考えられるか？
```

#### Step 4: 仮説の修正または確定
```
- 支持される → 確定
- 一部支持される → 修正
- 支持されない → 新仮説立案
```

### 検証方法の選択

| 検証方法 | 適用場面 | 例 |
|---------|---------|-----|
| **データ分析** | 既存データがある | 売上データ分析、相関分析 |
| **フェルミ推定** | データがない、概算でOK | 市場規模推計 |
| **Web検索** | 公開情報で確認可能 | 業界動向、競合情報 |
| **比較分析** | 複数選択肢の比較 | 参入方法の比較 |
| **シミュレーション** | 将来予測 | 価格変更の影響試算 |
| **ユーザー提供データ** | 内部データが必要 | 詳細な財務データ |

### 判断基準の設定

仮説を「確定」「修正」「棄却」する明確な基準を設定：

```
例: 価格弾力性の仮説

【仮説】価格を10%下げれば、販売量が20%増加する

【判断基準】
- 支持: 過去データで価格弾力性が-2.0以上
- 修正: 価格弾力性が-1.5～-2.0（増加率を修正）
- 棄却: 価格弾力性が-1.0未満
```

## 5. 仮説検証サイクル

### PDCAサイクルの活用

```
Plan (仮説立案)
  ↓
Do (データ収集・分析)
  ↓
Check (評価・判断)
  ↓
Act (仮説修正または確定)
  ↓
(繰り返し)
```

### 仮説の進化プロセス

```
第1段階: 粗い仮説
「売上減少は競合の影響」

↓ 検証

第2段階: 具体化した仮説
「競合Aの低価格戦略により、若年層が流出」

↓ 検証

第3段階: 精緻化した仮説
「競合Aの価格は当社より15%安く、価格感度の高い20-30代の40%が流出。ただし品質評価は当社が優位」

↓ 結論

「価格競争ではなく、品質・サービスの差別化で対抗すべき」
```

## 6. 実践例

### 例1: 新規市場参入

**状況**: 東南アジア市場への参入を検討

**仮説立案**:
```
【仮説1】ベトナムは市場成長率が高く、参入障壁が低い
【理由】
- GDP成長率が年7%
- 外資規制が緩和されている
- 既に日系企業の進出が多い

【検証方法】
- 各国のGDP成長率、市場規模の比較
- 規制環境の調査
- 参入障壁の評価（法規制、資本、技術）
```

**検証結果**:
```
- ベトナムGDP成長率: 7.0% ✓
- 市場規模: 3,000億円（予想より小さい）
- 参入障壁: 流通網の構築が課題

【修正仮説】
「ベトナムは成長性は高いが、市場規模が小さい。タイ（市場規模1兆円、成長率3%）とベトナムの組み合わせ戦略が良い」
```

### 例2: 売上減少対策

**状況**: 前年比で売上が10%減少

**仮説立案**:
```
【仮説1】市場全体の縮小が主因
【検証方法】業界統計の確認

【仮説2】競合への顧客流出が主因
【検証方法】顧客アンケート、シェア分析

【仮説3】自社製品の魅力低下が主因
【検証方法】NPS調査、商品評価
```

**検証結果**:
```
- 市場全体: -2%（縮小はわずか）
- 当社シェア: 30% → 25%（競合Aが20%→25%）
- NPS: 50 → 40（低下）

【結論】
競合流出と製品魅力低下の複合要因。
特に競合Aの新製品が当社の主力製品と競合している。
```

## 7. 仮説思考のピットフォール

### 落とし穴1: 確証バイアス

自分の仮説を支持するデータだけを集めてしまう。

**対策**:
- 反証を積極的に探す
- 「この仮説が間違っているとしたら？」と問う
- 複数の仮説を並行して検証

### 落とし穴2: 早すぎる確定

データ不十分なまま仮説を確定してしまう。

**対策**:
- 判断基準を事前に設定
- 最低限必要なデータを定義
- 「まだ確定できない」と判断する勇気

### 落とし穴3: 固執

最初の仮説に固執し、修正できない。

**対策**:
- 「仮説」はあくまで「仮」と認識
- 新しいデータが出たら柔軟に修正
- 複数の代替仮説を用意

### 落とし穴4: 検証不足

仮説を立てて満足し、検証しない。

**対策**:
- 仮説と検証方法をセットで立案
- 検証計画を明確にする
- 期限を設定

## 9. ケーススタディ

### ケース: コンビニの売上減少

**背景**: あるコンビニチェーンで売上が減少傾向

**初期仮説**:
```
「来店客数の減少が主因」
```

**検証**:
```
データ分析結果:
- 来店客数: 微減（-3%）
- 客単価: 大幅減（-12%）

→ 仮説修正
```

**修正仮説**:
```
「客単価の減少が主因。特に高単価商品の売上が減少」
```

**深掘り検証**:
```
商品別分析:
- 弁当: -15%
- 飲料: -5%
- スナック: +2%

時間帯別分析:
- ランチタイム: -20%
- その他: -5%

→ さらに具体化
```

**最終仮説**:
```
「ランチタイムの弁当売上減少が主因。周辺にファストフード店が増え、顧客が流出している可能性」
```

**検証**:
```
- 半径500m以内に3店舗のファストフード店が過去1年で開店
- 価格比較: ファストフード店の方が10-15%安い
- 顧客アンケート: 「最近ファストフードを利用」が40%

→ 仮説確定
```

**提言**:
```
- ランチタイム限定の弁当値下げ
- 差別化商品（高品質・健康志向）の投入
- ファストフード店にない商品カテゴリーの強化
```

## 10. 仮説思考の習慣化

### 日常の訓練

1. **なぜ？と問う習慣**
   - 日常の出来事に「なぜ？」と問いかける
   - 表面的な理由で満足しない

2. **予測する習慣**
   - ニュースを見たら、「次に何が起きるか」予測
   - 後で検証して精度を高める

3. **代替案を考える習慣**
   - 1つの選択肢だけでなく、常に3つ考える
   - 「他にないか？」と自問する

### チェックポイント

プロジェクトの各段階で以下を自問：

**仮説立案時**:
- [ ] 検証可能か？
- [ ] 具体的か？
- [ ] アクショナブルか？

**検証時**:
- [ ] 十分なデータを集めたか？
- [ ] 反証も探したか？
- [ ] 代替仮説は検討したか？

**結論時**:
- [ ] 仮説は支持されたか？
- [ ] 意思決定につながるか？
- [ ] 次のアクションは明確か？
